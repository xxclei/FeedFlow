# 02 - 视频模块（Video）

前置：阶段 1（需要 JWT 鉴权和账号）。Feed 系统的素材来源。

## 目标

发布视频（带封面）、视频详情、作者主页视频列表、mp4/封面文件上传到本地磁盘并由 Gin 静态托管。

## 接口设计

| 路由 | 鉴权 | 请求 → 响应 |
|---|---|---|
| POST /video/uploadVideo | JWT | multipart `file` → `{url, play_url}` |
| POST /video/uploadCover | JWT | multipart `file` → `{url, cover_url}` |
| POST /video/publish | JWT | `{title,description,play_url,cover_url}` → video 对象 |
| POST /video/listByAuthorID | 无 | `{author_id}` → `[video...]` |
| POST /video/getDetail | 无 | `{id}` → video 对象 |

> 上传和发布是**两步**：前端先传文件拿 URL，再调 publish 落库。

## 数据模型

```go
type Video struct {
    ID          uint      `gorm:"primaryKey" json:"id"`
    AuthorID    uint      `gorm:"index;not null" json:"author_id"`
    Username    string    `gorm:"type:varchar(255);not null" json:"username"`  // 冗余！
    Title       string    `gorm:"type:varchar(255);not null" json:"title"`
    Description string    `gorm:"type:varchar(255);" json:"description,omitempty"`
    PlayURL     string    `gorm:"type:varchar(255);not null" json:"play_url"`
    CoverURL    string    `gorm:"type:varchar(255);not null" json:"cover_url"`
    CreateTime  time.Time `gorm:"autoCreateTime" json:"create_time"`
    LikesCount  int64     `gorm:"column:likes_count;not null;default:0" json:"likes_count"`
    Popularity  int64     `gorm:"column:popularity;not null;default:0" json:"popularity"`
}
```

设计点：**冗余存 `username`**（反范式）——Feed 输出每条视频都带作者名，冗余后列表查询零 join。代价：改名后旧视频显示旧名（原项目接受了这个代价，并顺带解释了为什么 rename 时不更新 videos 表）。`likes_count`/`popularity` 是计数列，本阶段只建字段，由阶段 4/8 维护。

## 关键设计决策

**Q1：上传文件放哪、叫什么？** 本地磁盘 `.run/uploads/videos/<authorID>/<yyyyMMdd>/<随机hex>.mp4`（封面同结构）。要点：
- 大小白名单：视频 200MB、封面 10MB（`f.Size` 检查，`<<` 位移写法 `200 << 20`）
- 扩展名白名单：`.mp4` / `.jpg .jpeg .png .webp`（小写化再比对）
- 文件名用 `crypto/rand` 生成 16 字节 hex——**绝不用用户原始文件名**（路径穿越/覆盖/特殊字符全躲掉）
- Gin 静态服务：`r.Static("/static", "./.run/uploads")`

**Q2：返回给前端的 URL 是绝对还是相对？** 绝对：`scheme://host/static/...`，scheme 识别 `TLS` + `X-Forwarded-Proto` 头（兼容反代）。

**Q3：参数校验放哪层？** Service 层做业务校验（`TrimSpace` 后 title/play_url/cover_url 必填）；handler 只做"字段有没有传"的绑定层校验。

**Q4：publish 时 username 从哪来？** handler 拿 accountID 后调 `accountService.FindByID` 查出用户名再填进 Video——跨模块调用发生在 handler 组装阶段。

## 实现提示

Repo：`CreateVideo` / `GetByID` / `ListByAuthorID`（`order by create_time desc`）/ `IsExist`（用 First + `gorm.ErrRecordNotFound` 判断，供 like/comment 模块复用）/ `DeleteVideo`。

Handler 上传骨架：

```go
f, err := c.FormFile("file")            // multipart 字段名必须是 file
// 校验 size、ext
absDir := filepath.Join(".run", "uploads", "videos", fmt.Sprintf("%d", authorID), date)
os.MkdirAll(absDir, 0o755)
filename := randHex(16) + ext
c.SaveUploadedFile(f, filepath.Join(absDir, filename))
// path.Join 拼 URL（用 / 不要用 \）
```

原项目还有 `DeleteVideo`（service 里有属主校验 + 删详情缓存），但 **router 没注册这个路由**——你复刻时可以顺手注册上，算第一个"比原项目完整"的小改进。

## 常见的坑

- `c.FormFile` 的字段名和前端 form-data 的 key 不一致 → 一直报 missing file
- 文件路径拼 URL 时用 `filepath.Join`（Windows 会出 `\`）→ URL 要用 `path.Join`
- `gorm:"autoCreateTime"` 只对零值时间生效；handler 里手动 `CreateTime: time.Now()` 也行，二选一
- `.run/uploads` 目录不存在时 `SaveUploadedFile` 失败 → MkdirAll 一定要先做
- 上传大小受 Gin 默认内存限制影响不大，但 nginx 反代时 `client_max_body_size` 要调

## 验收清单

- [ ] curl 上传一个 mp4 → 返回的 url 浏览器能直接播放
- [ ] 传 .avi / 300MB 文件 → 400 且错误信息明确
- [ ] publish 后 getDetail 返回完整字段（likes_count=0）
- [ ] listByAuthorID 按时间倒序
- [ ] 未带 token publish → 401
