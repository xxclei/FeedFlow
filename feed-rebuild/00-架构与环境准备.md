# 00 - 架构总览 与 阶段0：项目骨架

## 全局架构（先刻在脑子里）

```
                     ┌──────────────────────────────┐
  Vue / Postman ───► │  API 进程 (cmd/main)          │
      HTTP/JSON      │  Gin 路由 + 中间件             │
                     │  Handler → Service → Repo     │
                     └──────┬───────┬───────┬───────┘
                            │       │       │
                     MySQL(必选)  Redis(可选) RabbitMQ(可选)
                            ▲       ▲       │ topic 消息
                            │       │       ▼
                     ┌──────┴───────┴───────┴───────┐
                     │  Worker 进程 (cmd/worker)     │
                     │  Like/Comment/Social Worker   │──► MySQL
                     │  PopularityWorker             │──► Redis
                     └──────────────────────────────┘
```

三条贯穿全程的**降级哲学**（这是本项目最大的工程特色，复刻时刻意练习）：

1. **启动时降级**：Redis/RabbitMQ 连不上 → 置 `nil`，日志提示后继续启动，功能整体禁用
2. **运行时按目标降级**：发 MQ 失败 → 只对失败的目标（MySQL 或 Redis）直接写
3. **请求级降级**：单个 Redis 命令失败 → 回源 MySQL，缓存操作一律 50ms 超时不阻塞主请求

## 阶段 0 目标

搭出能跑的骨架：配置加载 → 连 MySQL → GORM 自动建表 → Gin 起服务。**不写任何业务。**

## 要做的事

### 1. 配置模块 `internal/config/loadconfig.go`

- 定义 `Config` 结构：Server / Database / Redis / RabbitMQ 四段，yaml tag 小写
- `Load(filename string) (Config, error)`：读文件 + `yaml.Unmarshal`
- 依赖：`gopkg.in/yaml.v3`（`go get gopkg.in/yaml.v3`）

`configs/config.yaml`：

```yaml
server:
  port: 8080
database:
  host: 127.0.0.1
  port: 3307
  user: root
  password: "123456"
  dbname: myfeed
redis:
  host: 127.0.0.1
  port: 6379
  password: "123456"
  db: 0
rabbitmq:
  host: 127.0.0.1
  port: 5672
  username: admin
  password: password123
```

### 2. 数据库模块 `internal/db/db.go`

三个函数：

```go
func NewDB(cfg config.DatabaseConfig) (*gorm.DB, error)   // 拼 DSN + gorm.Open
func AutoMigrate(db *gorm.DB) error                        // db.AutoMigrate(&...)
func CloseDB(db *gorm.DB) error                            // db.DB() 拿 sqlDB 再 Close
```

DSN 模板（三个参数一个都不能少）：

```
%s:%s@tcp(%s:%d)/%s?charset=utf8mb4&parseTime=True&loc=Local
```

- `parseTime=True`：没有它，扫描 DATETIME 列直接报错
- `AutoMigrate` 初期只放 Account，之后**每完成一个模块就往里加一张表**

### 3. 入口 `cmd/main.go`

流程：`config.Load("configs/config.yaml")` → `db.NewDB` → `db.AutoMigrate` → `defer CloseDB` → Gin `r.Run(":port")`。
阶段 0 先不接 Redis/MQ，但把 `log.Printf` 的启动日志打好，方便排查。

> 注意：配置路径是**相对进程工作目录**的，必须 `cd myfeed && go run ./cmd` 运行（原项目 start.sh 就是这么做的）。

## 关键设计决策（动手前先想）

| 问题 | 原项目的答案 | 你要不要跟 |
|---|---|---|
| 配置返回值还是指针？ | 值 `(Config, error)`，上层取地址传参 | 均可 |
| 建表方式 | AutoMigrate（开发友好；生产应换 SQL 迁移） | 跟 |
| 配置读取库 | yaml.v3 + 结构体 tag（进阶可加 viper/env 覆盖） | 跟 |
| MySQL 时区 | DSN `loc=Local` + 容器 `TZ=Asia/Shanghai` | 跟，否则时间差 8 小时 |

## 常见的坑

- 忘 `parseTime=True` → `sql.Scan` 报错，报错信息完全不指向这里
- `go run cmd/main.go` 和 `go run ./cmd` 不一样：后者才是包方式运行
- 3307 端口写成 3306 → 连接拒绝（本机若装有 MySQL 极易踩）
- yaml 值里 `123456` 不加引号可能被解析成八进制/其他类型，密码类一律加引号
