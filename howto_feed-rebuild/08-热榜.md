# 08 - 热榜（滑动窗口 ZSET + 快照分页）★ 全项目最精巧

前置：阶段 7。抽象度最高的部分，建议先在 redis-cli 里手工把数据结构玩一遍再写代码。

## 目标

点赞/评论实时累加热度 → 分钟桶 ZSET；`/feed/listByPopularity` 读"最近 60 分钟"聚合榜，**翻页期间榜单冻结不抖动**；Redis 不可用时降级 MySQL 三游标分页。

## 热度模型

| 行为 | popularity 增量（MySQL） | 热榜 ZSET 增量（Redis） |
|---|---|---|
| 点赞 | +1 | +1 |
| 取消点赞 | -1 | -1 |
| 评论 | +1 | +1 |

（权重可自行设计，比如评论 +3；原项目就是 +1/-1。）

## 数据结构（先在 redis-cli 里玩）

```
写：ZINCRBY hot:video:1m:202609091405  1   "42"      ← 每分钟一个桶，member=videoID
    EXPIRE  hot:video:1m:202609091405  7200          ← 2h，够 60 分钟窗口 + 冗余

读：ZUNIONSTORE hot:video:merge:1m:202609091405  60
        hot:video:1m:202609091405  hot:video:1m:202609091404  ...（最近60个桶）
        AGGREGATE SUM
    EXPIRE  hot:video:merge:1m:202609091405  120    ← 快照只活 2 分钟
    ZREVRANGE hot:video:merge:1m:202609091405  0 9   ← 第 1 页（offset 分页）
```

## 接口协议（快照分页是核心思想）

```json
请求(第1页):  {"limit": 10, "as_of": 0, "offset": 0}
响应:         {"video_list": [...], "as_of": 1757393100, "next_offset": 10, "has_more": true}
请求(第2页):  {"limit": 10, "as_of": 1757393100, "offset": 10}   // as_of 原样带回来！
```

## 关键设计决策（每一条都是面试题）

**Q1：为什么不直接一个大 ZSET 累加？** 单 key 写竞争激烈；且历史热度永远累计无法表达"近期热门"。分钟桶 = 写分散 + 天然时间衰减（老桶过期即衰减）。

**Q2：为什么翻页要冻结榜单（as_of）？** 实时榜每秒都在变，第 1 页和第 2 页之间名次互换 → 重复/漏看。**快照 + offset** 让一次浏览会话看到同一版本的榜单。

**Q3：快照什么时候重建？** `as_of` 落到分钟，快照 key `hot:video:merge:1m:<yyyyMMddHHmm>` 带 2min TTL 且**先 EXISTS 判断**——同一分钟的后续请求复用，只有跨分钟/过期才重算。翻页通常 2 分钟内完成，够用。

**Q4：ZSET 里只有 videoID，详情哪来？** `GetByIDs` 一次 `IN` 查 MySQL 拿视频行，**再按 ZSET 返回的顺序重排**（IN 查询不保序！用 `map[uint]*Video` + 按 ids 序遍历）。

**Q5：怎么判断翻到底？** 请求的 offset 已超榜 → `ZRevRange` 返回空且 `offset>0` → 直接返回空列表 `has_more=false`（注意此时 next_offset 原样返回，不要再 +limit）。

**Q6：MySQL 降级版怎么分页？** 三字段复合游标（阶段 3 模式的三代目）：

```sql
ORDER BY popularity DESC, create_time DESC, id DESC
WHERE (popularity < ?) OR (popularity = ? AND create_time < ?)
   OR (popularity = ? AND create_time = ? AND id < ?)
```

响应同时携带两套游标（`as_of/offset` + `next_latest_popularity/before/id`），Redis 挂了前端拿 DB 游标继续翻。

**读路径骨架**：

```
if cache 可用:
    asOf = req.as_of>0 ? req.as_of : now，Truncate 到分钟
    生成 60 个桶 key（asOf 往前数 60 分钟）
    快照 key 不存在 → ZUnionStore(SUM) + Expire(2m)
    ZRevRange(快照, offset, offset+limit-1)
    成功且有数据 → ids → GetByIDs → 重排 → buildFeedVideos → 返回（as_of 回传）
    offset 超界 → 返回空 + has_more=false
    Redis 出错 → 落到下面
MySQL 降级：三游标查询 → 返回（as_of=0）
```

## 常见的坑

- 时区：桶 key 一定用 `UTC().Truncate(time.Minute)`，本地时间会导致"分桶错位"且和 as_of 对不上
- `Format("200601021504")` 这个参考时间写错一个字符，key 就乱
- `ZRevRange` 只回 member 不回 score（要 score 用 `ZRevRangeWithScores`，本接口只用排名所以 member 够）
- ZUnionStore 是 O(N*K)，60 桶 × 每桶成员数——别把窗口开成 24h（1440 桶）
- 降级版和 Redis 版的**排序语义不同**（累计 popularity vs 近1小时增量），属已知取舍，文档里写明即可
