# feed-rebuild：短视频 Feed 系统复刻指导手册

> 本文件夹是对 `../feedsystem_video_go` 的**模块化拆解 + 从零复刻指南**。
> 目标：你自己动手，按顺序把整个项目重写一遍。文档负责告诉你"做什么、想什么、怎么验收"，代码由你写。

## 怎么用这套文档

1. **先读 `00-架构与环境准备.md`**，建立全局认知，完成"阶段 0"（项目骨架）。
2. 按下面路线图**从上到下**逐阶段推进。每个阶段对应一篇文档。
3. 每篇文档结构统一：
   - **目标**：这个模块做完你能跑通什么
   - **前置依赖**：必须先完成哪些阶段
   - **接口/数据设计**：路由表、请求响应 JSON、表结构（照着定义，不用自己发明）
   - **关键设计决策**：动手前必须想清楚的问题（附原项目的答案做参考）
   - **实现提示**：函数签名 / 关键代码骨架（不含完整实现，留给你写）
   - **原项目对照**：原代码文件路径，卡住时去看标准答案
   - **常见的坑**：原作者踩过或差点踩的坑
   - **验收清单**：做到什么程度算完成
   - **进阶改进**：比原项目可以做得更好的地方（可选）

## 通用工程约定（全程遵守）

**分层规则**（每个业务模块目录内四件套）：

```
internal/<module>/
├── entity.go    # GORM 模型 + 请求/响应结构体
├── repo.go      # 只碰数据库（*Repository，方法接收 context）
├── service.go   # 业务逻辑、缓存/MQ 决策、参数校验
└── handler.go   # 参数绑定、状态码、调 service，不写业务
```

- 依赖注入在 `internal/http/router.go` 手工完成：new Repo → new Service → new Handler → 挂路由
- **所有 DB/Redis/MQ 方法第一个参数都是 `context.Context`**，handler 里传 `c.Request.Context()`
- 错误响应统一 `c.JSON(400/500, gin.H{"error": err.Error()})`；成功直接返回对象或 `gin.H{"message": ...}`（原项目无统一 wrapper，你可以在进阶改进中设计一个）
- 调用方判断"记录不存在"用 `errors.Is(err, gorm.ErrRecordNotFound)`；MySQL 唯一冲突用 `mysqlErr.Number == 1062`
- **每完成一个阶段就 `git commit`**（原项目的提交历史就是你的提交模板）
