# 01 - 账号模块（Account）+ JWT 鉴权【全量版】

前置：阶段 0。这是第一个业务模块，也是**鉴权体系**的地基，值得写慢。
本阶段做到与原项目**功能完全对齐**：注册/登录（双 token）/登出/改密/改名/查询/头像上传/资料编辑/刷新 token，外加 JWT 双中间件和 `apierror` 错误分类包。

> **对齐原则（全程适用）**：最终产出 = 原项目全部功能。若某能力依赖后续阶段（如 Redis 缓存、限流、getProfile 跨模块聚合），本阶段文档明确标注"阶段 N 回填"，绝无遗漏——每个能力都有归属阶段。

## 目标

- 注册（bcrypt 哈希）、登录（**双 token**：24h 访问 token + 长效刷新 token）、登出、改密（强制下线）、改名（重签 token）、按 ID/用户名查询
- **刷新 token**：`POST /account/refresh` 用 refreshToken 换新 accessToken（无感续期）
- **头像上传**：文件校验（类型/大小）→ 随机文件名 → 落盘 `.run/uploads/avatars/` → 返回绝对 URL
- **资料编辑**：bio / avatar_url 更新
- 两个鉴权中间件：`JWTAuth`（强）、`SoftJWTAuth`（软，阶段 6 用）
- `apierror` 包：统一把绑定/业务错误分类成合适的 HTTP 状态码

## 接口设计

| 路由 | 鉴权 | 限流(阶段7回填) | 请求 → 响应 |
|---|---|---|---|
| POST /account/register | 无 | 5次/时/IP | `{username,password}` → `{message}` |
| POST /account/login | 无 | 10次/分/IP | `{username,password}` → `{token, refresh_token, account_id, username}` |
| POST /account/refresh | 无 | - | `{refresh_token}` → `{token, account_id, username}`（新 accessToken） |
| POST /account/changePassword | 无 | - | `{username, old_password, new_password}` → `{message}` |
| POST /account/findByID | 无 | - | `{id}` → `{id, username, avatar_url?, bio?}` |
| POST /account/findByUsername | 无 | - | `{username}` → `{id, username}` |
| POST /account/logout | JWT | - | `{}` → `{message}` |
| POST /account/rename | JWT | - | `{new_username}` → `{token}`（**新 token！**） |
| POST /account/uploadAvatar | JWT | - | multipart `file` → `{avatar_url}`（绝对 URL） |

## 数据模型（全量，对照原项目 entity.go）

```go
type Account struct {
	ID           uint   `gorm:"primaryKey" json:"id"`
	Username     string `gorm:"unique" json:"username"`
	Password     string `json:"-"`                      // 敏感字段不序列化！
	Token        string `json:"-"`                      // 当前有效 accessToken（单会话撤销模型）
	RefreshToken string `json:"-"`                      // 当前有效 refreshToken
	AvatarURL    string `gorm:"type:varchar(512)" json:"avatar_url,omitempty"`
	Bio          string `gorm:"type:varchar(255)" json:"bio,omitempty"`
}
```

请求/响应结构体照原项目 entity.go 敲全：`CreateAccountRequest`、`LoginRequest/LoginResponse`、`RenameRequest`、`FindByIDRequest/FindByIDResponse`、`FindByUsernameRequest/FindByUsernameResponse`、`ChangePasswordRequest`、`UpdateProfileRequest`、`RefreshRequest`、`GetProfileRequest/GetProfileResponse`（后者阶段 6 回填用）。

## 关键设计决策（动手前先回答自己）

**Q1：密码怎么存？** bcrypt（`golang.org/x/crypto/bcrypt`）。哈希在 **Service 层**做；校验用 `bcrypt.CompareHashAndPassword`（盐内嵌在 `$2a$10$...` 哈希串里，无需单独盐列），绝不查出来比明文。

**Q2：JWT 里放什么、怎么撤销？** Claims = `{account_id, username}` + RegisteredClaims（HS256，24h，ExpiresAt/IssuedAt/NotBefore）。撤销方案是**单会话 token 模型**：`account.token` 列只存"当前有效的那个 token"——登录覆盖（顶号下线）、改名换新（旧 token 立即失效）、改密清空（全部下线）、登出清空。中间件比对请求 token 与存储 token，不一致 = 已撤销。**数据库即黑名单**。

**Q3：refreshToken 是什么、怎么轮换？** 登录时额外签发一个**不透明随机串**（`crypto/rand` 32 字节 hex，非 JWT，不需要过期解析）存进 `account.refresh_token`。`/refresh` 用它换新 accessToken：验证 refreshToken 与库中一致 → 签新 accessToken → 覆盖 `token` 列（旧 accessToken 立即作废）。**refreshToken 本身不轮换**（长期凭证），accessToken 短命。阶段 7 回填：Redis 缓存 `refresh:<token> → accountID` 加速查找，未命中回落扫库。

**Q4：secret 放哪？** 环境变量 `JWT_SECRET`，空则回落默认值（原项目为随机生成——重启全失效；你可用固定默认值，进阶：空值直接 fatal 更安全）。

**Q5：中间件怎么把身份传给 handler？** `c.Set("accountID", claims.AccountID)`，配套 `getAccountID(c *gin.Context) (uint, error)`（注意 `c.Get` 拿出的是 `any`，要 `.(uint)` 断言）。

**Q6：注册/改名时用户名冲突怎么识别？** 捕获 MySQL 错误码 1062（dup key）→ `ErrUsernameTaken` → HTTP 409。**不要先查再插**（并发窗口）。注册冲突在 repo 层翻译（`CreateAccount`），改名冲突在 service 层翻译（`RenameWithToken` 事务里撞的）。

**Q7：头像文件怎么存？** 落本地磁盘 `.run/uploads/avatars/<accountID>/`（`.gitignore` 已忽略 `.run/`），文件名用 `crypto/rand` 16 字节 hex + 原扩展名（**防路径猜测/覆盖**），URL 拼绝对地址（scheme 判断 TLS / X-Forwarded-Proto，host 用 `c.Request.Host`）。handler 做全部校验：大小 ≤10MB、扩展名白名单 .jpg/.jpeg/.png/.webp。

**Q8：登录失败的错误怎么返回？** 原项目用户不存在/密码错误均 500（粗糙）。**改进**：统一 `ErrInvalidCredentials` → handler 映射 401，防"用户名枚举"攻击（攻击者靠不同响应探测哪些用户名存在）。

## 实现提示

**`internal/auth/jwt.go`**（独立于 account，供中间件和 service 共用）：

```go
func jwtSecret() []byte                                  // env 优先，缓存
func GenerateToken(accountID uint, username string) (string, error)   // HS256, 24h
func GenerateRefreshToken(accountID uint) (string, error)             // rand 32B → hex
func ParseToken(tokenString string) (*Claims, error)     // ParseWithClaims + 校验 alg
```

`ParseToken` 的 keyFunc 里**必须校验签名算法**（防算法混淆攻击）：

```go
if token.Method == nil || token.Method.Alg() != jwt.SigningMethodHS256.Alg() {
	return nil, errors.New("unexpected signing method")
}
```

**Repo 层要点**（`CreateAccount / FindByID / FindByUsername / Login / Logout / RenameWithToken / ChangePassword / UpdateToken / UpdateAvatar / UpdateFields / FindAll`）：

- `Login(ctx, id, token, refreshToken)`：`Updates(map[string]interface{}{...})` 一次写两个 token
- `Logout`：token 和 refresh_token **都清空**（改密后 refresh 也得死）
- `RenameWithToken` 用 **`db.Transaction`** 把"改名"和"写新 token"放进一个事务
- 所有 Update 之后检查 `result.RowsAffected == 0` → 返回 `gorm.ErrRecordNotFound`
- `CreateAccount` 里 `errors.As` 翻 1062 → `ErrUsernameTaken`

**Service 层**（`CreateAccount / Login / Logout / ChangePassword / Rename / RefreshAccessToken / FindByID / FindByUsername / UpdateAvatar / UpdateProfile`）：

- `Login` 返回 `(accessToken, refreshToken, error)`：查人 → bcrypt 验 → 签双 token → `repo.Login` 存库
- `RefreshAccessToken(ctx, refreshToken) (newToken, accountID, username, error)`：阶段 1 版本 `FindAll` 扫库比对 refreshToken（原项目 Redis 优先、未命中扫库——**阶段 7 回填缓存快路径**）
- `ChangePassword`：验旧密码 → 哈希新密码 → 更新 → `Logout`（refresh 一起清，全部下线）
- `Rename`：空名校验 → 先签新 token → `RenameWithToken` 事务 → 翻译 1062

**Handler 层**（对照原项目 handler.go，注意 `apierror.ClassifyHTTPStatus(err)` 用于参数绑定错误）：

- `Login` 里原项目先 `FindByUsername` 一次再调 service（service 内部还会查一次）——**冗余点**，你可以直接用 service 返回的 accountID/username 拼 `LoginResponse`
- `UploadAvatar`：`c.FormFile("file")` → 大小/扩展名校验 → `os.MkdirAll` → `randHex(16)` 文件名 → `c.SaveUploadedFile` → `path.Join` 拼 URL → `buildAbsoluteURL` → service.UpdateAvatar
- 错误映射：`ErrUsernameTaken`→409、`ErrNewUsernameRequired`→400、`gorm.ErrRecordNotFound`→404、`ErrInvalidCredentials`→401（改进）、其余 500

**`internal/apierror/errors.go`**（独立小包）：`ClassifyHTTPStatus(err) int`——绑定校验类错误（gin 的 validator 错误）返回 400，其余 500。原项目就几十行，先读再抄。

**鉴权中间件骨架**（`internal/middleware/jwt/jwt.go`）：

```
JWTAuth:      无 Authorization header → 401
              格式非 "Bearer xxx"（SplitN 2 段 + EqualFold）→ 401
              ParseToken 失败 → 401
              check() 校验存储 token
SoftJWTAuth:  无 header → 直接 c.Next()（匿名放行，阶段 6 Feed 用）
              有 header 但非法 → 401（带了就必须是对的）
check():      （阶段 7 会插入 Redis 优先逻辑，现在直接查 DB）
              FindByID → account.Token == "" 或 != 请求 token → 401 "token has been revoked"
              通过 → c.Set(accountID/username) → c.Next()
```

## 难点清单（本阶段真正难的地方）

1. **双 token 轮换链路**：accessToken 短命可撤销，refreshToken 长命免登录——谁存哪、谁覆盖谁、改密后谁死，全要推演清楚（画表：register/login/refresh/logout/rename/changePassword 六个场景 × token/refresh_token 两列的值变化）
2. **头像上传的安全细节**：大小上限、扩展名白名单、随机文件名、MkdirAll 权限、绝对 URL 拼接（X-Forwarded-Proto）——每一条都是实际生产里踩出来的
3. **1062 的两个翻译点**：注册在 repo 翻、改名在 service 翻（因为撞键位置不同），错误要保持"同一业务语义"
4. **防用户名枚举**：登录"查无此人"和"密码错误"必须不可区分
5. **事务原子性**：改名+换 token 必须同生共死，否则出现"名字换了旧 token 还活着"的身份错位

## 亮点（原项目在账号模块的工程亮点）

- **单会话撤销模型**：无需黑名单表，一行存储位即可实现"登出/顶号/改密即失效"
- **apierror 错误分类**：错误 → HTTP 状态码的映射收敛到一个包，handler 不再散落魔法数字
- **静态文件 + 绝对 URL**：上传即返回可直接访问的完整链接，前端零拼接
- **限流中间件预告**：注册 5次/时/IP、登录 10次/分/IP（`internal/middleware/ratelimit`，阶段 7 回填进路由）

## 常见的坑

- `Password`/`Token`/`RefreshToken` 忘加 `json:"-"` → 凭证直接返回给前端（安全事故级 bug）
- 断言 `c.Get("accountID").(uint)`：GORM 主键是 uint，断言成 int64 会 panic/失败
- `SplitN(header, " ", 2)` 后不检查 `len(parts)!=2` → 越界 panic；`Bearer` 大小写用 `EqualFold`
- 改密接口用 username 定位用户（原项目如此），意味着你得先知道明文旧密码——注意它和 rename 的鉴权设计不一致，是原项目的一个粗糙点，你可以改进为"从 token 取 accountID"
- bcrypt 的 `DefaultCost`(10) 首次注册会明显耗时（~100ms），是正常现象
- `path.Join`（URL 用 `/`）和 `filepath.Join`（磁盘路径，Windows 是 `\`）别混用
- 登出后再登出：中间件已拦（token 已清），别在 service 里对空 token 做多余处理

## 验收清单

- [ ] 注册 → 登录拿到 `{token, refresh_token}` → 带 `Authorization: Bearer <token>` 调 logout 成功
- [ ] 登出后**用同一个 token** 再调 logout → 401 token has been revoked
- [ ] 重复注册同名 → 409；重复 rename 成已有名 → 409
- [ ] rename 返回新 token，**旧 token 立即 401**
- [ ] changePassword 成功后旧 token 全部失效（含 refresh_token），新密码能登录
- [ ] `/account/refresh` 用 refresh_token 换到新 token，旧 access token 失效
- [ ] uploadAvatar 上传 png → 返回的 URL 浏览器能直接打开；传 .txt → 400；传 >10MB → 400
- [ ] updateProfile 改 bio → findByID 能看到新 bio
- [ ] 数据库里 password 是 `$2a$10$...` 格式；refresh_token 是 64 位 hex
- [ ] `GET /healthz` 返回 ok；上传的头像经 `/static/avatars/...` 可访问
