# 04 - 点赞模块（Like）

前置：阶段 3。第一个"写热点"模块——计数并发正确性 + 幂等，是阶段 9 异步化的基础。

## 目标

点赞/取消点赞（维护 likes 表 + videos.likes_count）、判断是否点赞、我点赞过的视频列表；Feed 的 `is_liked` 从假变真。

## 接口设计

| 路由 | 鉴权 | 请求 → 响应 |
|---|---|---|
| POST /like/like | JWT | `{video_id}` → `{message}` |
| POST /like/unlike | JWT | `{video_id}` → `{message}` |
| POST /like/isLiked | JWT | `{video_id}` → `{is_liked}` |
| POST /like/listMyLikedVideos | JWT | `{}` → `[video...]` |

## 数据模型

```go
type Like struct {
    ID        uint      `gorm:"primaryKey" json:"id"`
    VideoID   uint      `gorm:"uniqueIndex:idx_like_video_account;not null" json:"video_id"`
    AccountID uint      `gorm:"uniqueIndex:idx_like_video_account;not null" json:"account_id"`
    CreatedAt time.Time `json:"created_at"`
}
```

**复合唯一索引 `(video_id, account_id)` 是本模块的基石**：数据库层面保证一人一赞，幂等兜底全靠它。

## 关键设计决策

**Q1：怎么保证不重复点赞？** Service 先 `IsLiked` 预检（给用户友好报错），但**真正的防线是唯一索引**：并发双击时 insert 第二次必报 1062，捕获后转成"已点赞"业务错误。预检 + 索引双层防御缺一不可。

**Q2：计数怎么加？** **绝不允许**读出 likes_count、加 1、写回（丢更新）。原子 SQL：

```go
UpdateColumn("likes_count", gorm.Expr("GREATEST(likes_count + ?, 0)", change))
```

`GREATEST(...,0)` 防止 unlike 竞态把计数打成负数。`UpdateColumn` 跳过 GORM 钩子，纯改列。

**Q3：点赞要不要顺手更新 popularity？** 要（热度 = 互动信号）。本阶段直写：`popularity = GREATEST(popularity+change, 0)`。阶段 9 会把它改成发 MQ 异步。

**Q4： unlike 时怎么知道计数该不该减？** `Delete` 的 `RowsAffected`：删到行才减计数。这个判断在阶段 9 的 Worker 幂等里是**同款套路**，现在养成习惯。

**Q5：我的点赞列表怎么查？** LIKE 表 JOIN videos：

```sql
SELECT videos.* FROM videos
JOIN likes ON likes.video_id = videos.id
WHERE likes.account_id = ?
ORDER BY likes.created_at DESC
```

## 常见的坑

- 唯一索引建反/没建 → 并发测试重复计数；写完去 `show index from likes` 确认
- `gorm.Expr` 里写 `likes_count + 1` 字符串拼接 OK，但**变更量必须参数化** `+ ?`
- 预检和插入之间有时间窗，单靠预检挡不住并发双击——所以 1062 分支必写
- isLiked 对不存在的 video 应返回 false 而不是报错（看你的产品定义，原项目返回 false）
- 判断 1062：`errors.As(err, &mysqlErr) && mysqlErr.Number == 1062`，不是 `err.Error()` 字符串匹配

## 验收清单

- [ ] 连点 5 次 like → 1 次成功 4 次"已点赞"，likes_count == 1
- [ ] unlike 后 likes_count == 0，再 unlike → "未点赞"错误，计数不为负
- [ ] 两个账号分别点赞同一视频 → 计数 == 2
- [ ] 登录状态下访问 listLatest → 自己点过赞的视频 `is_liked: true`，其他 false
- [ ] listMyLikedVideos 顺序 = 点赞时间倒序
- [ ] **并发压测**（ab/hey 或 go 例程 50 并发点赞）→ 计数仍然正确
